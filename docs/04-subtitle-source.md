# 字幕来源：把动画角色做成卡

这条路和「复刻某个真人」共用同一条管道，只是第一步换了——输入不是聊天记录 JSON，
而是**字幕文件**。

## 为什么换字幕

- **不涉及真人。** 角色是虚构的，没有同意问题，也没有隐私风险。
- **素材容易找。** 字幕是现成的，不需要任何导出、解密或抓取。
- **格式标准。** `.srt` / `.ass` 结构固定，解析起来比五花八门的聊天记录导出稳定得多。

## srt2txt.py 认什么

| 输入 | 说明 |
|---|---|
| `.srt` | 最常见。块状结构：序号 / 时间轴 / 台词 |
| `.ass` | 动画字幕的主流格式。会剥掉 `{\\pos(...)}`、`{\\c&H...}` 这类样式标签 |

两种都只读文本，不碰视频文件。

```bash
# 先看这份字幕里有哪些说话人
python srt2txt.py -i ep01.srt --list-speakers

# 转换
python srt2txt.py -i ep01.srt -o ep01.txt --date 2024-01-01
```

## 说话人是怎么认出来的

按行首的「名字：台词」前缀提取。没有前缀时，用 `--speaker 角色名` 指定，整份都算这个角色。

ASS 文件里的 `Name` 字段（样式名或角色名）也会被当作说话人。

一份字幕里混了路人和配角是常态——转出来的 txt 里会一并出现。用 `analyze.py --char-name`
指定你要的那个角色就行。**名字写错会直接报错并列出实际有哪些人**，不会静默出一份空报告。

## `--date` 是干什么的

字幕的时间戳是**剧内时间**（第几分钟），没有日期。而 `analyze.py` 的月度统计需要日期。

所以给每一集打一个日期：第 1 集打 `2024-01-01`、第 2 集打 `2024-02-01`……

几集一起统计时，[2] 那条曲线就从「关系热度」变成了「**角色戏份分布**」——
哪一集她的台词多，一眼能看出来。

## 九维度里哪些要忽略

| # | 维度 | 对字幕 |
|---|---|---|
| 1 | 消息长度分布 | ✅ 有效 |
| 2 | 每月消息量 | ⚠️ 当「戏份分布」读 |
| 3 | 活跃时段 | ❌ **无意义**（那是剧内时间，不是作息） |
| 4 | 方括号表情 | ✅ 有效 |
| 5 | Unicode emoji | ✅ 有效 |
| 6 | 口头禅候选 | ✅ 有效 |
| 7 | 高频词片段 | ✅ 有效 |
| 8 | 句尾习惯 | ✅ 有效 |
| 9 | 连发密度 | ✅ 有效 |

九个里八个能用。写卡时跳过 [3] 就对了。

实际跑一份样本（4 集、255 条台词）出来的结果：

```
[4] 方括号表情排行（含摊薄率）
    [星星]  × 13   每 13 条出现 1 次
    [笑脸]  × 10   每 16 条出现 1 次

[6] 口头禅候选
    「呐呐，你听我说」 × 11
    「真的吗真的吗」   × 11
    「早上好呀」       × 10

[8] 句尾习惯
    「！」结尾 × 60     ← 元气角色，数据自己说出来了
```

## 语料的边界

- ✅ 动画 / 影视 / 广播剧字幕
- ✅ 自己整理的剧本、小说对话
- ❌ **游戏文本解包** —— 那涉及逆向工程，性质和「去读微信数据库」是一回事，本项目不碰

另外一条：**工具能做，别人的角色卡别公开发布。**
你自己做多少张都无所谓，但不要把带具体角色名和官方台词的卡传出去——这是社区的默契，也是版权线。
