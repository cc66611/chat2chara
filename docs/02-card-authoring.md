# 角色卡撰写指南

## chara_card_v2 的结构

SillyTavern 的角色卡是一份 JSON。核心字段：

| 字段 | 作用 | 影响强度 |
|---|---|---|
| `description` | 身份、外貌、生活背景 | 中（会随对话变淡） |
| `personality` | 性格条目 | 中（会随对话变淡） |
| `scenario` | 开场场景设定 | 中 |
| `first_mes` | 第一条消息 | **强（行数被模仿）** |
| `mes_example` | 对话示例 | **强（说话方式被模仿）** |
| `post_history_instructions` | 每轮注入的行为指令 | **最强** |
| `character_book` | 世界书，按触发词检索 | 中（省 token 的关键） |
| `alternate_greetings` | 备选开场白 | 中 |

**关键认知**：前四项会随着对话进行逐渐被稀释——聊到 50 轮，`description` 里写的性格早就被冲淡了。

所以真正维持角色一致性的，是 **`mes_example`（示范风格）+ `post_history_instructions`（持续施压）** 这两项。

## description 怎么写

### 原则：只写有依据的

这一栏最容易写飞。不要因为「感觉她应该是这样」就写进去。

**有依据的写法：**

> 说话极短极碎：一半消息不超过 5 个字，一件事拆成两三条连发，很少超过四条。

（依据：`analyze.py` 输出「≤5字 占 90.2%」「连发密度 平均 2.26 条/回合」）

**没依据的写法：**

> 她性格温柔善良，很会照顾人，内心其实很渴望被爱。

（这四句话可以套在任何一个人身上，等于什么都没说。）

### 结构建议

按「身份 → 外貌 → 生活 → 语言特征」的顺序组织：

1. **身份**：职业、年龄、地域——有数据支撑的才写
2. **外貌**：如果记录里有提到
3. **生活背景**：作息、习惯、养的宠物、常做的事
4. **语言特征**：这一步最关键，把统计结果转述成自然语言

### 关于「真实细节」

删掉那些**看起来生动、但其实是编的**细节。

「她喜欢在雨天听陈绮贞」这种句子读起来很有味道，但它不是从数据里来的，模型会把它当成事实反复引用，最后角色会活成一个你想象中的人，而不是记录里的那个人。

**宁可少写，不要编。**

## personality 怎么写

### 用编号条目

模型对编号条目的服从度高于散文段落。原理很简单：编号条目有明确的边界，模型能清楚地知道「这是第 3 条，要满足」。

### 每条尽量挂数字

```
① 说话极短极碎：一半消息不超过 5 个字，一件事拆成两三条连发，很少超过四条。
② 口头禅：亲亲（892 次）、乐了（611 次）、没事儿（548 次）、服了（402 次）。
③ 句尾爱带「嘛」「呀」「～」。
④ 被撩会炸毛：用词是「滚」「变态」「打你」。
⑤ 生气不吵架，只回「行」「噢」，等对方递台阶。
⑥ 关心人是命令式短句：喝点热水、多喝水、早点睡。
```

**为什么数字有效**：它给了模型一个可量化的锚点。「口头禅是亲亲」模型可能会过度使用；「亲亲出现了 892 次，在几十万条消息里」模型就知道这是低频的。

### 情绪要分层写

人的情绪反应不是单一的。至少要区分：

- **假生气**（打情骂俏）：用什么词
- **真生气**：怎么表现，持续多久，怎么结束
- **开心**：怎么表达
- **难过**：是直接说还是憋着

`analyze.py` 的第 6、8 项能给你这些线索。

## mes_example 怎么写

**这一栏是行数的源头。**

模型会严格模仿示例的格式。示例里回复几行，模型就输出几行。

### 建议

- 写 **4-6 组**，覆盖典型场景（日常、关心、吃醋、生气、撒娇、道别）
- 每组回复**不超过 5 行**
- 组之间用空行分隔

### 格式

```
{{user}}: 我今天不太舒服
{{char}}: 咋了
哪里不舒服

摸摸
没事儿
早点睡

{{user}}: 晚安
{{char}}: 睡觉觉吧
晚安安[月亮][月亮]
亲亲
```

### 三条禁忌

**一、不要写时间跳跃**

示例里绝对不能出现「（过了一会）」「三秒后」这种示范——模型会学，然后每次对话都自己跳时间。

**二、不要替 {{user}} 说话**

示例只能示范 `{{char}}` 的回复。如果你在示例里替用户写了心情和动作，模型会学着替用户说话。

**三、不要写超长回复**

哪怕某次真实对话里对方真的发了一大段，也不要放进示例。示例是**示范常态**，不是展示全部。放一个 10 行的例子进去，模型就次次给你 10 行。

## post_history_instructions 怎么写

**这是最强的控制器**，每一轮对话都会注入。

因为它是持续注入的，所以它对抗的是「对话变长后被稀释」这个问题。

### 必须包含的四类规则

**一、行数控制**

```
每次回复最多 3-5 行短句，宁少勿多——一次说不完的话就留到下一轮再说，绝不一次倾倒。
```

**二、稀有元素用摊薄率**

```
[微笑] 是稀有表情（在全部记录里平均每 214 条消息才出现 1 次）：
只在她真心阴阳怪气时偶尔出现，绝大多数回复里禁止使用。
```

**三、一轮一停**

```
一轮只回应当前这句话，说完就停，把话头交回对方。
```

**四、四条禁令**（逐条列出，不要笼统）

```
禁止替对方说话、禁止自己接自己的话、禁止自设时间流逝（如「过了一会」「三秒后」）、
禁止在对方没回复时连续推进剧情、禁止责怪对方没回消息。
```

**为什么禁令要逐条列？**

因为「不要抢戏」太笼统，模型不知道具体指什么。而「禁止自设时间流逝」「禁止责怪对方没回消息」是具体行为，模型能准确识别并避免。

## character_book 怎么写

### 它的价值：省 token + 按需唤醒

世界书条目不常驻上下文，只在**触发词命中时**才被插入。

这意味着你可以写很详细的背景设定，而不占用常驻 token。

### 条目设计

每条包含：

```json
{
  "keys": ["触发词1", "触发词2"],
  "content": "触发后插入的内容",
  "enabled": true,
  "insertion_order": 1
}
```

- **keys**：触发词要覆盖这个场景下可能出现的说法。比如「生气」这条，keys 应该包含 `["生气", "不开心", "炸毛", "凶我"]`
- **content**：写具体的设定细节
- **insertion_order**：数字越小优先级越高

### 建议 8-15 条

覆盖这些方向：

| 方向 | 例 |
|---|---|
| 称呼习惯 | 怎么叫对方，随情绪怎么变 |
| 说话方式 | 口头禅、连发习惯 |
| 情绪模式 | 生气/开心/难过分别怎么表现 |
| 工作/日常 | 职业相关的话题 |
| 兴趣爱好 | 会主动聊什么 |
| 关系背景 | 共同经历、约定、梗 |
| 特殊习惯 | 独有的口头禅、仪式感 |

### 触发词要够宽

触发词太窄会出现「明明聊到了这个话题，世界书却没触发」。

**好**：`["猫", "狗狗", "宠物", "毛孩子"]`
**差**：`["我家的猫叫小白"]`

## alternate_greetings

备选开场白，让角色有多个入口。

建议写 2-3 条，覆盖**不同情绪状态**下的开场：

- 一条日常平静的
- 一条带着情绪的（生气、撒娇、冷战）
- 一条在特殊场景下的（深夜、刚忙完）

这样换开场白就等于换了一种关系的切入口。

## 最后：自检清单

填完卡之后，逐条问自己：

- [ ] 每一条性格设定，我都能说出依据来自哪一个统计数字吗？
- [ ] `first_mes` 和每组示例的回复，都在 6 行以内吗？
- [ ] 稀有元素的摊薄率，我抄进 `post_history_instructions` 了吗？
- [ ] 「一轮一停」和四条禁令，都写进 `post_history_instructions` 了吗？
- [ ] 示例里有没有出现时间跳跃？（有就删）
- [ ] 示例里有没有替 `{{user}}` 说话？（有就删）
- [ ] 世界书的触发词，够不够宽？
- [ ] **卡里有没有任何可以定位到真人的信息？**（如果打算分享，这一条是硬性的）

答案全是「是」，就可以部署了。
